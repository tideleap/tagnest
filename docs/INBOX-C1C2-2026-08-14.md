# B-1 设计决策：C1/C2 浏览器扩展增强 + 收件箱（2026-08-14）

任务 #198（B-1a 调研）产出。基于代码证据，非推测。

## 1. 收件箱数据模型：**复用派生语义，不加列、不迁移**

`functions/_lib/db.ts:383-402` 的 `scopeClause('inbox')` 已实现：

```sql
b.deleted_at IS NULL AND b.is_archived = 0
AND NOT EXISTS (SELECT 1 FROM bookmark_tags bt WHERE bt.bookmark_id = b.id)
```

即收件箱 = 「未删除、未归档、无任何标签」的派生集合。`SCOPES`（bookmarks/index.ts:11）已含 `'inbox'`，前端已全面接入：

- 路由 `/library/inbox`（LibraryPage VALID_SCOPES）
- Sidebar 导航 + 角标（`Sidebar.tsx:179` inbox = stats.untagged）
- MobileTabBar、CommandPalette（nav-inbox）、全局快捷键 `i`、登录后默认落地页

**决策：不新增 inbox 列、不写迁移 0018。** 派生语义天然满足 C2「新收藏先进缓冲区」：扩展保存的书签无标签 → 自动进收件箱；用户打标（或 AI 建议被接受）→ 自动离开收件箱 = 「确认后归档」。零状态机、零数据迁移风险。

## 2. 私密过滤（调研项 ⑤）

`listBookmarks`（db.ts:506）的 WHERE 基础子句已含 `PRIVATE_BOOKMARK_CLAUSE`，inbox scope 与其叠加，私密书签不会出现在收件箱列表。无需额外处理。

## 3. 扩展 API 契约（调研项 ③④）

扩展经 `X-API-Key`（tnk_ 密钥）从 service worker 出站，无 host_permissions，攻击面小。现有能力与缺口：

| 能力 | 现状 |
|---|---|
| 一键收藏当前页 | ✅ popup save-page → ensureBookmark |
| 整窗收纳 + 标签页组 | ✅ capture-window + createGroup/addGroupItem |
| 窗口快捷键 Ctrl+Shift+T | ✅ manifest commands |
| 409 幂等（已存在视为成功） | ✅ err.detail.id 回传 |
| **选中文字存为笔记** | ❌ 缺失（C1 核心缺口） |
| **单页收藏快捷键** | ❌ 缺失 |
| **已存在书签追加笔记** | ❌ ensureBookmark 硬编码 `note: null`，409 时笔记丢失 |

后端契约已就绪，**无需新端点**：

- `POST /api/bookmarks` 接受 `note`（≤20000 字符）、`tagNames`（≤30）
- `GET /api/bookmarks/:id` 返回完整书签含 note
- `PATCH /api/bookmarks/:id` 支持 `note` 字段更新（[id].ts:103）
- 409 响应 `detail.id` → 扩展可直接 GET→PATCH 追加

## 4. 实施清单（端点零改动，纯扩展 + 测试 + 文案）

6. **后端契约测试**：inbox scope 行为（无标签可见/打标后离开/私密不出现）——dbMock 端点级
7. **前端**：收件箱空态文案引导（扩展收藏 → 打标归档闭环说明）

## 5. 风险与边界

- 选区注入仅在用户主动触发（popup 按钮/快捷键）时发生，符合 activeTab 语义，无需 `<all_urls>`
- appendNote 为「读取-改写-写入」，并发追加可能丢写；单用户扩展场景可接受，记录在案
- 笔记追加采用换行拼接，不做去重（重复保存同段选区属用户意图）
