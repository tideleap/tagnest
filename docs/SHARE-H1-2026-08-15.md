## 2. 密码保护方案

**存储**：迁移 0018 `ALTER TABLE shares ADD COLUMN password_hash TEXT`（NULL = 无密码）。复用 `hashPassword(password, env)` / `verifyPassword`——与登录密码同一 PBKDF2 参数，不引入新算法。

**API 契约**：
- POST/PATCH /shares 接受 `password?: string | null`：非空字符串 → 哈希存储；`null` → 清除密码；省略 → 不变（PATCH 语义与 expiresInDays 一致）
- mapShare 只暴露 `hasPassword: boolean`，哈希永不出库
- GET /api/public/:slug：
  - 有密码且请求无 `X-Share-Password` 头 → **401** + `{ requiresPassword: true, title, palette }`（只给渲染密码框所需的最小信息，不泄露条目）
  - 密码错误 → **403**（与 401 区分，前端可提示「密码不对」）
  - 密码正确 → 正常渲染
- **密码保护分享绕过 KV 缓存与 public Cache-Control**：缓存会跨访客泄露内容；改回 no-store。无密码分享行为完全不变。

**前端**：SharePage 收到 401 requiresPassword → 渲染密码输入框（沿用分享页 palette），提交后带 `X-Share-Password` 头重试；成功后密码存入 sessionStorage（`share-pass:{slug}`），同会话刷新免重输；403 → 行内错误「访问密码不正确」。

## 3. 集合级分享方案

**存储**：同一迁移 `ALTER TABLE shares ADD COLUMN collection_id TEXT`（NULL = 标签查询模式）。

**语义**：`collectionId` 与 `tagIds` 互斥——给了 collectionId 则 tagIds/matchAllTags 忽略（后端强制清空，避免两种过滤叠加的歧义）。

**渲染**：renderShare 分支——collectionId 存在时查
`collection_bookmarks cb JOIN bookmarks b`（同 PRIVATE_BOOKMARK_CLAUSE + deleted_at IS NULL + is_archived=0，ORDER BY cb.position）。集合被删 → 分享页 404「分享页不存在或已关闭」（与停用同语义，不确认集合曾存在）。

**UI**：SharesSection 表单加「内容来源」切换：标签筛选（现状）/ 指定集合（下拉选集合）。列表项徽标显示来源类型。

## 5. 边界与风险

- 密码哈希复用登录基建，但分享密码**不做登录限流**——公开端点加限流需独立 bucket 设计，超出本次范围；PBKDF2 100k 迭代本身已是成本闸门（文档记录为已知限制）
- KV 缓存绕过只影响有密码的分享；既有公开分享性能路径零变化
- 集合内私密/类别私密书签在渲染层被 PRIVATE_BOOKMARK_CLAUSE 过滤，与标签分享一致
- PATCH 省略 password = 不变，与 EXPIRY_KEEP 哨兵同构，编辑不会意外清除密码
