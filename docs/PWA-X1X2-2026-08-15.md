## 2. Web Share Target 方案（关键决策）

**用 GET 方法，不用 POST**：
- Android Chrome 对 GET share_target 支持最稳；POST + multipart 需要后端新增表单解析端点，而分享场景只需要 url/title/text 三个字符串，query 参数足够。
- 接收端是**前端路由** `/share-target`，不是后端端点——浏览器把系统分享转成一次普通导航，SW 的导航离线回退天然覆盖。

**后端零改动**：保存复用现有 `POST /api/bookmarks`（无 tagNames → 自动进收件箱，B-1 已闭环）。与扩展收藏走同一条创建路径，AI 富化/快照 waitUntil 逻辑全部继承。

**认证流**：`/share-target` 路由放在 RequireAuth 内。未登录时 RequireAuth 重定向 `/signin` 并携带 `state.from = pathname + search`（App.tsx:81），登录后 AuthPage 的 `safeFromTarget` 校验通过（单斜杠开头的同源路径）自动跳回，分享参数不丢。

**参数解析（parseShareTarget 纯函数）**：
- `url` 参数存在且是合法 http(s) → 直接用
- 否则从 `text` 中提取第一个 http(s) URL（部分 App 只分享纯文本）
- `title` 缺省 → 用 text 去掉 URL 后的剩余文字，再缺省 → 域名兜底（后端 titleFallback 二次兜底）
- `text` 中 URL 之外的剩余文字 → 存为笔记（与扩展「选中文字存笔记」语义对齐）
- 无合法 URL → 页面展示手动输入态，不静默失败

## 3. 离线策略（X1/X2）

- **不新建 offline.html**：导航请求已回退到缓存的 index.html shell，React 应用能完整渲染；缺的只是「数据断了」的提示。
- **OfflineBanner 组件**：监听 `online/offline` 事件 + `navigator.onLine` 初始值，离线时在 AppLayout 顶部显示非阻断横幅「当前离线：可以浏览已加载的内容，保存操作需恢复网络」。放在 TopBar 之上，z-index 低于命令面板。
- sw.js `CACHE_VERSION` v3 → v4：manifest 内容变更（share_target + 颜色），强制刷新预缓存的 manifest.webmanifest。

## 5. 边界与风险

- share_target 只在支持 Web Share Target 的系统（Android Chrome 为主）出现「TagNest」分享目标；iOS Safari 不支持，降级为「添加到主屏 + 手动收藏」，不影响既有功能
- 分享导航是全新页面加载，auth bootstrap（refresh cookie）先于 RequireAuth 判定，已登录用户无感直达接收页
- text 提取 URL 用保守正则（http/https 开头、非空白结尾），误提取风险低；提取失败回退手动输入而非报错
- 重复分享同一 URL → 后端 409「该网址已在书签库中」，接收页展示错误文案，不产生重复项（与扩展行为一致）
