# B-11 RSS 订阅（自动拉取收藏）设计文档

> 日期：2026-08-16 · 模块：Y4/H3 迁移包 + 分享 RSS 的 RSS 子项
> 状态：**已落地并门禁通过**（迁移 `0022_feeds.sql` + 后端 + 前端 + 测试）

## 1. 范围与结论

B-11 原始路线包含「实例间迁移包」与「分享 RSS」两部分。探索阶段已确认：

- 导入子系统（HTML/JSON/CSV 导入、导出、WebDAV/S3 备份推送）**已完整上线**，迁移包能力事实存在；
- 整个代码库中 **RSS 订阅为零**——没有任何 feeds 表、端点或前端入口。

因此 B-11 收敛为 **RSS 订阅 + 自动拉取收藏**：用户添加 RSS/Atom 源，新条目被解析后去重写入书签库并按订阅源级默认标签归类。

「自动」由两层保障：

1. 手动：每个订阅源有「刷新」按钮，列表顶部有「刷新全部」；
2. 定时：`feeds.cadence`（off/hourly/daily/weekly）描述理想频率，`POST /api/feeds/refresh-all` 只刷新「到期」的订阅源，天然成为未来 cron 调度（wrangler.toml 暂无 trigger）的触发点。

## 2. 数据模型

迁移 `migrations/0022_feeds.sql`：

```sql
CREATE TABLE IF NOT EXISTS feeds (
  id             TEXT PRIMARY KEY,
  user_id        TEXT NOT NULL,
  title          TEXT NOT NULL DEFAULT '',
  url            TEXT NOT NULL,
  tag_names      TEXT NOT NULL DEFAULT '[]',   -- JSON 数组
  cadence        TEXT NOT NULL DEFAULT 'off',
  last_fetched_at TEXT,
  last_status    TEXT,
  created_at     TEXT NOT NULL,
  updated_at     TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_feeds_user ON feeds(user_id);
```

设计取舍：

- `tag_names` 用 JSON 列而非多对多表——订阅源数量远小于书签数量，且「订阅源级默认标签」是直读字段，避免为低频关系开一张表。
- `last_status` 存机器状态（`ok`/`empty`/`http_###`/`feed_blocked_host`/`feed_fetch_failed`/`feed_invalid_url`/`never`），前端映射为中文徽标。

## 3. 后端

### 3.1 解析与刷新库 `functions/_lib/feed.ts`

- `parseFeed(xml)`：**纯函数**，无第三方 XML 解析器（与导入子系统用正则解析 HTML 的取向一致）。容错处理 RSS 2.0 与 Atom：
  - 标题/描述剥 CDATA 并解码 `&amp; &lt; &gt; &quot; &#39; &apos; &nbsp;`；
  - 链接同时支持 RSS `<link>text</link>` 与 Atom `<link rel="alternate" href="…"/>`（跳过 `rel="self"`）；
  - 日期经 `Date.parse` 归一为 ISO，无法解析则 `null`；
  - 无链接的条目直接丢弃（无法去重，跳过）。
- `refreshFeed(env, userId, feed, fetcher?)`：注入式 fetcher（默认带 10s 超时的 `fetch`，UA 标识 `TagNest-Feed-Fetcher/1.0`）。流程：
  1. 校验主机 `isBlockedHost`（纵深防御，订阅时也已校验）；
  2. fetch → 非 2xx 抛 `feed_fetch_failed`；
  3. `parseFeed` → 空则记 `empty` 返回；
  4. 按 `urlKey` 批量查已有书签（`queryInChunks` 规避 D1 100 参数上限）做去重；
  5. `ensureTags(feed.tagNames)` 取得默认标签 id；
  6. 新条目 `INSERT OR IGNORE INTO bookmarks` + `bookmark_tags`，按 90 条一批 `batch()` 避免 D1 100 语句上限；
  7. 记录 `last_status='ok'` 与 `last_fetched_at`。
  - 返回 `{added, skipped, failed}`，落库失败不回滚（逐条 OR IGNORE，单条坏数据只影响自己）。

### 3.2 端点（`functions/api/feeds/`）

| 方法 / 路径 | 作用 | 说明 |
|---|---|---|
| `GET /api/feeds` | 列出订阅 | `ORDER BY created_at DESC`，仅本用户 |
| `POST /api/feeds` | 订阅 | 校验 URL（`parseUrl`）+ `isBlockedHost` 拦截；`ensureTags`；201 返回 |
| `DELETE /api/feeds/:id` | 退订 | 越权 404 |
| `POST /api/feeds/:id/refresh` | 手动刷新单个 | 404 未知源；返回 `FeedRefreshResult` |
| `POST /api/feeds/refresh-all` | 刷新所有到期源 | 单源失败不中断其余；返回 `{results, refreshed, added}` |

所有端点复用 `requireUserId` / `ApiException` / `json(no-store)` 现有范式；错误码对用户可读（`feed_invalid_url` / `feed_blocked_host` / `feed_fetch_failed`）。

## 5. 安全

- SSRF：`isBlockedHost`（字面主机分类，fail-closed）同时应用于订阅校验与刷新（纵深防御）。Cloudflare Workers 无法解析 fetch 的目标 IP，故只能校验字面主机；`redirect: 'follow'` 下若重定向到内网，连接会被平台拒绝，显式守卫给出诚实错误。
- 越权：所有端点以 `user_id` 过滤/校验归属，跨用户 404。
- 超时：拉取 10s 硬超时，避免挂起。
