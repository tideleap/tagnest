## 四、关键风险与发现（PM 必须知情）

### R1 文档漂移（高）— 会误导任何后续判断
- `REVIEW-2026-08-01.md` 仍称 O5/O6/O7/O8/O9 「未实现 / 部分 / 明文存储」——**全部与现状相反**。
- `README.md` Features 章节**未提及** API 密钥、公开分享、拖拽排序、登录限流。
- 影响：投资人 / 接手同学 / 你自己据此评估会严重低估产品成熟度。

### R2 测试覆盖缺口（高）— CI 绿 ≠ 新功能有守护
- `scripts/smoke.sh`（51 项）与 `tests/`（60 项 vitest）均写于 O5/O6/O7/O9 之前。
- 新端点（keys CRUD、shares CRUD、`/s/:slug`、reorder、throttle）**无任何单元或 e2e 测试**。
- 影响：对密钥 / 分享逻辑的回归不会在 CI 暴露，等于裸奔上线。

### R3 生产开放注册（中）
- 公开 URL `tagnest.pages.dev` 当前**任何人可注册**。作为对外站点，是垃圾账号 / 滥用向量的入口。
- 缓解：O4 一行配置即可关闭（`DISABLE_SIGNUP=true`），但属产品决策（是否要对外拉新）。

### R4 KV 缓存未闭环（中/低）
- `public/[slug].ts` 已实现 KV 缓存读取/写入，但 `wrangler.toml` 未绑定 KV 命名空间 → 代码优雅降级，分享页每次回源 D1（仅 60s 浏览器/边缘 Cache-Control）。
- 影响：分享页被大量传播时，D1 读压力未被边缘缓存吸收。需绑定 KV 才真正「加速」。

### R5 安全凭证卫生（运维）
- 对话中曾明文暴露一个 GitHub PAT（建议立即到 GitHub 撤销轮换）。
- 验证阶段在**生产 D1 写入了 1 个测试账号 + 1 条书签**，应清理。
- 本机 GCM 仍缓存旧 PAT。

### R6 无可观测性（中）
- 生产无错误上报、无可用性监控、无业务埋点。故障对用户先于你发现。Cloudflare 自带 Analytics 可用作最低限度，但异常无告警。

### R7 工具链版本（低）
- 本地 `wrangler 3.114.17`，官方已到 4.118.0。此前 `d1 migrations apply` 失败即是 3.x 怪癖；升级后可走正规迁移流程。
