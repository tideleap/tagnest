# 网站快照（网站预览图片）功能

> 目标：书签卡片的「网站预览」不再靠远程缩略图，而是走 **截图生成 → 存入 Cloudflare R2 → 卡片展示首方图片** 的完整闭环。

## 架构

```
保存书签 (POST /api/bookmarks)
   └─ 有截图能力时，ctx.waitUntil 异步：
        截图提供方(二选一) ──> R2 对象 snapshots/{userId}/{bookmarkId}.webp
                              └─> bookmarks.snapshot_key = 该 key

手动刷新 (POST /api/bookmarks/:id/snapshot)  ← 同一生成链路，同步返回

卡片展示：snapshot_key 存在 → <img src="/api/snapshots/{key}">
          └─> GET /api/snapshots/:key 流式返回对象 + 一年强缓存
```

## 截图提供方（优先级）

| 优先级 | 提供方 | 何时启用 | 说明 |
|---|---|---|---|
| 1 | **Cloudflare Browser Run**（`[browser]` 绑定） | `SNAPSHOT_API_URL` 未设，但账号已开通 Browser Run | 在 Cloudflare 自家网络上截图，无第三方依赖、无 API key、无数据中心 IP 封禁问题。**推荐**。 |
| 2 | 外部截图 API（`SNAPSHOT_API_URL`） | 你显式设置它 | 支持 `{url}` 占位（替换为编码后的目标 URL），可选 `SNAPSHOT_API_KEY` 作为 `Bearer`。 |
| — | 无 | 两者都不可用 | 快照跳过，卡片回落远程 `coverUrl` → 圆形色块（不报错）。 |

> **为什么不用「免费无 key 的第三方 API」做默认**：实测多个免费截图服务（如 sitelookeratter）
> 会对 Cloudflare / 数据中心 IP 返回 401，即使带浏览器 UA——这是按 IP 封禁，无法从代码绕过。
> 可靠且无此问题的唯一本平台方案就是 **Cloudflare Browser Run**（跑在 CF 自己的网络上）。

## 你需要做的（沙箱内无法代办）

### 1. R2 桶 + 开通 Browser Run
- R2 桶 `tagnest-media`（APAC）已创建。
- **开通 Cloudflare Browser Run**：Cloudflare 控制台 → Workers & Pages → **Browser Run**（免费
  计划可用）。之后 `wrangler.toml` 里的 `[browser] binding = "BROWSER"` 才会生效。

### 2. 绑定是否随部署生效
`wrangler.toml` 已加入：
```toml
[[r2_buckets]]
binding = "SNAPSHOT_BUCKET"
bucket_name = "tagnest-media"

[browser]
binding = "BROWSER"
```
`compatibility_date` 已提升到 `2026-03-24`（Browser Run `.quickAction()` 的最低要求）。

### 3. （可选）改用外部截图 API
若你不想用 Browser Run，而是用它方服务：
| 变量 | 说明 |
|---|---|
| `SNAPSHOT_API_URL` | 截图服务地址，支持 `{url}` 占位；`SNAPSHOT_API_KEY` 可选（作为 `Bearer`） |
注意：Page 环境变量按部署绑定——改了后需重新部署才能生效。

### 4. 迁移
`migrations/0007_snapshot_r2.sql` 新增 `bookmarks.snapshot_key` 列。部署时 `deploy.yml`
若无 D1 权限会降级跳过，列缺失时相关 SELECT 会失败 → 需确保迁移在发布前已应用：
```bash
node scripts/migrate.mjs
```
