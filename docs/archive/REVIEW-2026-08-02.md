## 二、必须修复（P0 — 安全/正确性，建议立即处理）

### 1. 🔴 SSRF 重定向绕过（安全）
`functions/api/metadata.ts:48-51`
- **问题**：`redirect: 'follow'` 只对初始 `target.hostname` 做 `BLOCKED_HOSTS` 校验（line 34）。服务端可返回 302 把 fetch 重定向到 `http://localhost/`、`http://169.254.169.254/`（云元数据端点）等被禁目标，绕过检查。
- **建议**：改 `redirect: 'manual'`，循环里每次 `Location` 用 `parseUrl` 重新走 `BLOCKED_HOSTS`；或用 `redirect: 'error'` 直接拒绝任何重定向（metadata 提取用不到跟随跳转）。

### 2. 🔴 导入失败计数逻辑缺陷
`functions/api/import/commit.ts:167-171`
- **问题**：单批次抛错时 `failed += chunk.length` 且 `imported -= chunk.length`，但 `chunk` 中可能含被 `skipDuplicates` 跳过的项（已计入 `skipped`）。导致同一 URL 既算 skipped 又算 failed，`imported` 被超额扣减——用户看到的"成功/失败/跳过"数字可能自相矛盾。
- **建议**：用 `chunk` 中**实际新增 bookmarks 语句条数**度量 `failed`（语句里 bookmark INSERT 的数量），或把 `skipped` 独立在 batch 外、失败只针对真正尝试插入的条数。

### 3. 🟠 标签/分享 slug 并发竞态 → 500（健壮性）
`functions/_lib/db.ts:166-183`（ensureTags）、`functions/api/shares/index.ts:34-37+70-91`、`functions/api/shares/[id].ts:38-48`
- **问题**：均为"先 SELECT 查重再 INSERT/UPDATE"到唯一索引列，无 `INSERT OR IGNORE`。两个并发请求同建同名标签、同用自定义 slug 时，后者触发唯一约束抛**未捕获 D1 错误 → 500**（应为 409）。
- **建议**：`ensureTags` 改用 `INSERT OR IGNORE ... RETURNING id`（与 import 部分一致）；shares 提交结构捕获 `SQLITE_CONSTRAINT` 转 `conflict('slug 已被占用')`。

### 4. 🟠 bulk-tag 单次 batch 语句过多 → 潜在超限
`functions/api/bookmarks/bulk-tag.ts:35-69`
- **问题**：`ownedIds`(≤500) × `addTagNames`(≤30) 最多累积 **15,000 条 INSERT** 塞进单次 `env.DB.batch()`。D1 单请求有语句数/体积上限，超大场景直接失败；单事务也会拉长持锁时间。
- **建议**：按固定大小（如每 500 条）分批 `batch`；或将标签 join 改写为一条 `INSERT OR IGNORE ... SELECT`（CROSS JOIN 一张 VALUES 派生表）。

### 5. 🟠 前端编辑态水合被覆盖（数据丢失可能）
`src/components/bookmark/BookmarkEditor.tsx:24-32`
- **问题**：水合 `useEffect` 依赖 `[bookmark]`；编辑过程中若该 query 被失效重取（其他写操作触发 `keys.bookmarkRoot` 失效），`bookmark` 对象刷新会把用户**正在输入的表单字段回滚**。
- **建议**：仅首次（用 `hasHydratedRef`）或 `bookmark.id` 变化时水合；后续失效字段用乐观更新保留。

## 三、建议优化（P1 — 性能/健壮性，高价值）

### 6. 🟠 TabGroupsPage 添加书签搜索无防抖 + 请求竞态
`src/pages/TabGroupsPage.tsx:434-450, 490-493`
- **问题**：每个 keystroke 直接 `runSearch`（两次串行 await：`/bookmarks` + `/tab-groups/:id`），无防抖、无 AbortController/序号保护。快速输入时旧响应覆盖新结果，且每次键入都重复请求 group 详情。
- **建议**：接入已有的 `useDebounced`；用 `AbortController` 或请求序号取最后响应；group 成员一次缓存避免每次重取。

### 7. 🟠 BookmarkCard memo 失效（大列表重渲染）
`src/pages/LibraryPage.tsx:144-168 + src/components/bookmark/BookmarkCard.tsx:341`
- **问题**：`cardHandlers` 每次渲染新建对象、内联箭头函数新引用，传给 `memo(BookmarkCard)` 后被浅比较判为变化 → 选区/滚动/父级重渲染时**所有卡片都重渲染**，memo 形同虚设。
- **建议**：handlers 用 `useCallback` 固化（依赖项为 bookmarks 操作）；或卡片内部从 store 取动作、props 只传最小数据。

### 8. 🟠 RemoteImage 失败状态不随 src 重置
`src/components/ui/RemoteImage.tsx:25-35`
- **问题**：`failed` state 在 `src` 变化时不重置；若某次加载失败后 src 更新（如 favicon URL 变化），fallback 永久展示。
- **建议**：`useEffect(() => setFailed(false), [src])`，或按 `src` 作为 key 强制重挂载。

### 9. 🟠 AI 富化 N+1 写
`functions/_lib/ai.ts:282-291`（applyEnrichment）
- **问题**：对模型返回的每个 tag 逐条 `INSERT OR IGNORE ... .run()`，每标签一次往返。
- **建议**：累积成 `env.DB.batch()`，与 `setBookmarkTags` 一致。

### 10. 🟠 导出全量物化 + 相关子查询
`functions/api/export.ts:37-63`
- **问题**：`SELECT ... .all()` 整库载入内存，`GROUP_CONCAT` 为每行相关子查询；书签量大时占满 Workers 内存。
- **建议**：分批查询 + `ReadableStream` 流式输出（对齐 import/commit 的 NDJSON 模式）；或至少限制 `GROUP_CONCAT` 为预聚合子查询一次。

### 11. ⚪ listBookmarks 每次列表请求都跑 COUNT
`functions/_lib/db.ts:397-403`
- **问题**：分页查询外无条件 `COUNT(*)` 聚合；滚动分页（客户端不展示总数）时多余。
- **建议**：`total` 惰性计算（仅当显式请求）。

### 12. ⚪ 无限滚动 effect 依赖不稳定数组
`src/pages/LibraryPage.tsx:207-213`
- **问题**：effect 依赖 `virtualRows`（每渲染都是新数组），同 tick 内、`isFetchingNextPage` 更新前可能重复 `fetchNextPage`。
- **建议**：将触底判定改为稳定计算（最后 index 阈值），或守卫式单次调度。

## 四、代码规范 / 可维护性（P2 — 建议抽空处理）

### 13. 🟡 硬编码字段长度魔法值散落
`functions/api/bookmarks/index.ts:91-95`、`bookmarks/[id].ts:49-56`、`metadata.ts:102/127`、`shares/index.ts:81`
- **问题**：`slice(0,300/500/2000/20000/120)` 等在多个 handler 用字面量重复，与 migrations 列定义对应却无共享常量。改一处忘一处 → 写入截断或 DB 报错。
- **建议**：建 `shared/constants.ts`（或 `_lib/constraints.ts`）集中 `TITLE_MAX`/`DESC_MAX`/`NOTE_MAX`/`URL_MAX` 等并替换。

### 14. 🟡 `MAX_*` 上限常量无统一出处
`bookmarks/index.ts:21`、`reorder.ts:20`、`import/preview.ts:11-14`、`keys/index.ts:17`、`metadata.ts:9`、`shares/index.ts:9`、`tab-groups/[id]/items.ts:6`
- **问题**：各 endpoint 各自命名、各自背常量（如 `MAX_BYTES` 在 metadata=512K 与 import=20M 概念重叠）。前端 `ImportPage.tsx:21` 还重复一份 20M。
- **建议**：上移至共享常量模块；前后端共用一份（前端 `src/lib/import-error.ts` 已部分引用）。

### 15. 🟡 重复错误消息字符串
`bookmarks/index.ts:62`、`[id].ts:11/24/89/103`、`metadata.ts:30`、`shares/index.ts:27`
- **问题**：`"网址格式不正确"`、`"书签不存在"`（x4）、`"该网址已在书签库中"` 在多文件重复硬编码；extension 端还要手工匹配语义。
- **建议**：集中错误文案表（或至少共享 code 常量），前端 classify 与之对齐。

### 16. 🟡 死代码
`src/pages/TabGroupsPage.tsx:442`
- **问题**：`new Set(page.items.filter(() => false).map(...))` 恒空，紧接被真实 `ids` 覆盖，可删。
- **建议**：删除。

### 17. 🟡 重复实现 sha256Hex
`functions/_lib/auth.ts:158-161` vs `functions/_lib/crypto.ts:111-114`
- **建议**：auth.ts 改从 `./crypto` 导入，删除本地副本。

### 18. 🟡 loadExistingKeys 两处重复
`functions/api/import/commit.ts:209-227` vs `functions/api/import/preview.ts:217-238`
- **建议**：抽到 `_lib` 公共模块复用。

### 19. 🟡 过时/误导注释
`functions/_lib/ai.ts` 头部、`functions/api/ai/settings.ts:10-15`、`migrations/0001_init.sql:81`（"nothing sends a request" / "Written by nothing today"）、`tests/db.test.ts:15-21`
- **问题**：ai.ts 已写库，注释却称未接线，严重误导维护者（也与 F-P1-6 台账口径冲突）。
- **建议**：更新为现状；AI 若下线则明确清理。

### 20. 🟡 `useGlobalHotkeys` 清理不完整
`src/hooks/useGlobalHotkeys.ts:68-92`
- **问题**：g 前缀序列的监听器与 900ms 定时器未纳入 hook 清理；登出卸载组件时泄漏；快速连按 `g` 会叠加监听。
- **建议**：把内部监听/定时器纳入单一 `useEffect` 返回的清理函数。

### 21. 🟡 TagFormDialog / GroupFormDialog 重复
`src/pages/TagsPage.tsx:216-324` vs `src/pages/TabGroupsPage.tsx:311-410`
- **建议**：抽取通用「命名+色板」表单组件或 `useNamedColorForm` hook；三个对话框的 `lastKey` 重置反模式统一为 `useResetOnChange`。

### 22. 🟡 构建缓存堆积
`.wrangler/tmp/`（680+ 个随机 bundle 目录）
- **问题**：每次 `wrangler pages dev` 生成新目录从不清理，本地磁盘膨胀（不进 git，已 ignore）。
- **建议**：`npm run dev:api` 前清理，或脚本 `clean`：`rm -rf .wrangler/tmp`（本地）。

## 五、测试覆盖缺口（P1 — 需补的关键路径）

**结论：后端 213 用例/24 文件、前端 24 用例/4 文件，lint/typecheck/build 全绿；但覆盖面严重偏向纯函数，高风险链路几乎无 handler 级测试。**

### 25. 🔴 API handler 级测试几乎为零
31 个 endpoint 中仅 `import/preview` 有真实 handler 测试。完全无测试：
- bookmarks CRUD（index/[id]/visit/trash/restore/purge/reorder/bulk-tag）
- export（含 CSV 公式注入防护）、metadata（SSRF）、stats 真实查询
- shares / public、tab-groups、ai/settings、tags（merge/index）、keys
- auth 全部端点（login/register/refresh/logout/me）——认证是最高风险面
- `_middleware.ts` 全局鉴权/API key 分发

**建议**：用 `tests/_support/dbMock.ts` 扩展 bookmarks/tags/bookmark_tags/shares/tab_groups 表，为上述端点的**正常 + 错误/边界分支**补 handler 级测试。优先 auth、export、metadata、bulk-tag、restore/purge。

### 26. 🔴 `functions/_lib/*` 有专属测试盲区
- `crypto.ts`、`env.ts`：零引用。
- `db.ts`：只测 colorForName/cursor/SORTS，核心 `listBookmarks`/`loadBookmark`/`ensureTags`/`setBookmarkTags` 无覆盖。
- auth/shares/tabgroups 只测纯函数，未测真实 DB 交互。

### 27. 🟡 前端覆盖缺口大
50 个前端文件仅 4 个被测。完全无测试：`stores/auth.ts`、`BookmarkCard`、`BookmarkEditor`、`CommandPalette`、全部 `hooks/queries/*`、全部 pages、ErrorBoundary。

**建议**：至少补核心冒烟测试：auth store、BookmarkCard 渲染+操作、CommandPalette 键盘、一个关键 page（LibraryPage 或 BookmarkEditor）。

### 28. 🟡 coverage include 只看 `_lib`，API handler 隐身
`vitest.backend.config.ts` coverage.include 仅 `functions/_lib/**`（且 exclude env.ts），`functions/api/**` 完全不计入 → 覆盖率数字虚高，最易错路径无保护。
**建议**：include 扩到 `functions/**`，先接受真实数字下降，再针对性补齐。

### 29. 🟡 错误/边界分支测试缺失（已核实）
- `apikeys.test.ts`：未测 delete 不存在 key、权限不足、expiresAt 过境。
