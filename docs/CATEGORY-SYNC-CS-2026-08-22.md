## 1. 背景与目标

### 1.1 用户原始需求

> "优化项目 AI 整理分类，不是简单只给网站打标签，重点在于网站分类。比如我在浏览器保存了 100 多个书签，这些书签是无序和凌乱的，通过 AI 整理能够将网站书签进行精确分类整理，然后可以和浏览器的书签进行同步。我想要的是能在浏览器之间相互切换的线上书签，可随时与浏览器的书签栏进行同步。"

拆解为三个递进目标：

1. **精确分类**：100+ 无序书签 → AI 整理成清晰的分类树，每条书签有**唯一、精确**的归属（不是堆一堆标签）。
2. **分类即结构**：分类结果能落到浏览器书签栏，变成真实的文件夹结构，随时可同步。
3. **跨浏览器切换**：线上书签库是唯一事实源，在公司电脑、家里电脑、不同浏览器之间切换时，拿到的都是同一套整理好的书签。

### 1.2 现状差距分析（代码证据）

| # | 差距 | 证据 | 影响 |
|---|---|---|---|
| G1 | AI 整理是"多标签"语义，不是"唯一分类" | `tag_suggestions` 一条书签可有多条 pending 建议；`max_tags` 默认 4 | 书签没有唯一归属，无法一一对应到文件夹 |
| G2 | 三级分组作用于**标签名**而非**书签内容** | `grouping.ts` `classifyTag(tag.name)` 按关键词规则给标签归位 | 未命中标签名的书签留在"未分类"，分类不彻底 |
| G3 | 上行同步丢弃浏览器文件夹结构 | `sync-diff.js` `flattenBrowserBookmarks` 只保留 URL 叶子节点 | 用户在浏览器里建好的文件夹语义全部丢失 |
| G4 | 下行回写是**平铺**的 | `reconcile.js` `resolveSyncFolder()` 把所有书签塞进书签栏下一个 "TagNest" 文件夹 | 云端分类再好，浏览器里看到的还是一坨 |
| G5 | sync-pull 响应不含分类路径 | `sync-pull.ts` 返回 `{id, urlKey, url, title, tagNames, updatedAt, deletedAt}` | 扩展无法知道每条书签该放哪个文件夹 |
| G6 | 无多设备/多浏览器视角 | 无 devices 表；API Key 无设备语义 | 用户无法知道"哪几个浏览器同步了、状态如何" |

**结论**：分类引擎（M3）与同步通道（M11）各自完备，但中间缺了一座桥——**"唯一分类 ↔ 文件夹结构"的双向映射**。本升级就是补这座桥。

### 1.3 已确认的产品决策

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| D1 | 回写策略 | **托管文件夹优先**：分类树写入书签栏下的 `TagNest` 托管文件夹，不动用户原有书签结构；后续可选"提升为整个书签栏" | 安全、可逆、不破坏用户数据 |
| D2 | 归属模型 | **单一主分类 + 标签辅助**：每条书签有且只有一个主分类（对应文件夹位置），现有标签保留为辅助筛选维度 | 文件夹语义天然唯一；保留标签不丢现有能力 |
| D3 | 浏览器范围 | **Chrome + Edge 优先**（共用 MV3 扩展包），Firefox/Safari 后续 | 覆盖主力用户，最快落地 |

由上述决策派生的设计约定：

- **D4 分类树复用标签树表达**：一级分类 = 顶层标签，二级子类 = 二级标签，不新建独立分类表体系（最小改动，复用 `tags.parent_id`、嵌套标签、合并审计等全部既有能力）。
- **D5 托管文件夹内的文件夹变更 = 重分类意图**：用户在浏览器里把书签从 `TagNest/开发技术/前端` 拖到 `TagNest/在线工具`，上行同步时视为"用户重分类"，写回云端并进入反馈学习——这是分类越用越准的关键闭环。
- **D6 云端为唯一事实源**：沿用 hub-and-spoke 模型；分类冲突以云端为基准，用户在托管文件夹的手动调整除外（D5 优先）。

## 2. 核心概念与映射规则

### 2.1 概念定义

| 概念 | 定义 |
|---|---|
| 主分类（Primary Category） | 书签的唯一精确归属，是分类树上的一个节点路径（如 `开发技术 > 前端开发`） |
| 分类树 | 由标签树（`tags.parent_id`）表达的 ≤3 层结构；顶层标签 = 一级分类 |
| 辅助标签 | 书签上除主分类路径外的其他标签，仅用于筛选，不参与文件夹映射 |
| 托管文件夹 | 书签栏下名为 `TagNest` 的文件夹，内部结构 = 云端分类树的镜像 |
| 分类路径（categoryPath） | 书签主分类的文件夹路径数组，如 `["开发技术", "前端开发"]` |

### 2.2 云端 ⇄ 浏览器映射规则

```
云端分类树                          浏览器书签栏
─────────────                      ─────────────────────
开发技术 (一级标签)          ⇄     书签栏/
  └─ 前端开发 (二级标签)              └─ TagNest/            ← 托管文件夹
       ├─ react.dev                        ├─ 开发技术/
       └─ vuejs.org                        │    └─ 前端开发/
在线工具 (一级标签)                        │         ├─ react.dev
  └─ figma.com                             │         └─ vuejs.org
未分类（无主分类的书签）                    ├─ 在线工具/
                                           │    └─ figma.com
                                           └─ 未分类/          ← 兜底文件夹
```

映射规则（确定性、可测试）：

| # | 规则 | 说明 |
|---|---|---|
| R1 | 主分类路径 = 文件夹路径 | 一级分类 → 一级文件夹；二级子类 → 二级文件夹；书签落在路径末端 |
| R2 | 无主分类 → `未分类` 文件夹 | 兜底，保证托管文件夹完整镜像云端 |
| R3 | 同一 URL 全局唯一 | 托管文件夹内外出现同一 URL 时，以 `url_key` 去重；托管文件夹内的位置为准 |
| R4 | 托管文件夹外的书签不受回写影响 | 回写只操作托管文件夹内部；外部书签只上行、不改写 |
| R5 | 文件夹重命名/移动 = 分类调整信号 | 托管文件夹内的结构变更上行时映射为分类变更（D5） |
| R6 | 层级上限 3 层 | 与分类树一致；浏览器侧更深的文件夹上行时压平到第 3 层 |

## 3. 功能需求

### C1 AI 精确分类引擎（从"打标签"到"定归属"）

| 编号 | 需求 | 验收标准 | 现有实现 | 需要的改动 |
|---|---|---|---|---|
| C1-1 | 单一主分类输出 | 每条书签产出唯一 `{一级, 二级, 置信度, 理由}`；不再产出多个平级标签作为归属 | `engine.ts` 产出 `tags[]` 多候选 | 新增分类模式提示词：输出单归属结构化 JSON；复用稳健解析/修复轮/精准补偿 |
| C1-2 | 基于内容分类 | 输入 = 标题 + URL + 描述 + 可选正文摘要；分类依据是页面内容而非标签名 | `enrich.ts` 内容抓取已就位 | 提示词改为直接对书签内容归类（绕过"先打标签再归组"的间接路径，解决 G2） |
| C1-3 | 分类树约束 | 归属必须落在既有分类树节点上；确需新分类时进入"新分类建议"待审，不自动膨胀树 | `taxonomy-tree.ts` `attachParentTags` 已有树锚定 | 复用；新增"新节点建议"审阅类型 |
| C1-4 | 全量整理 100~2000 条 | 100 条 ≤5 分钟；进度可见；断点续跑；成本预估前置 | 批处理/任务/预估全部已就位 | 任务 `kind` 增加 `categorize` |
| C1-5 | 置信度分流 | ≥ 自动应用阈值（默认 0.8）直接落库；低于阈值进审阅队列；域名兜底结果强制 `needsReview` | `auto_apply_threshold` + 审阅队列已就位 | 复用 |
| C1-6 | 分类保护规则 | 同域名/同项目页面倾向同一分类；尊重用户已确认的历史归属 | `scoring.ts` 同域加权 + `feedback.ts` | 反馈键从 (标签,域名) 扩展为 (分类路径,域名) |
| C1-7 | 未分类清零目标 | 一次全量整理后，未分类书签占比 ≤10%（其余为抓取失败/内容模糊，标记待人工） | 当前无此指标 | 任务结果统计新增 `uncategorized` 计数 |

### C2 分类树与审阅界面

| 编号 | 需求 | 验收标准 | 现有实现 | 需要的改动 |
|---|---|---|---|---|
| C2-1 | 分类树视图 | 树状展示一级/二级分类 + 每节点书签数；支持展开折叠 | 侧栏标签树已有三级折叠；`/library` 已有"分类"视图（`categoryGroups.ts`） | 分类视图改为**按主分类唯一归属**渲染（当前是多标签多归属，同一书签会出现在多个分类下） |
| C2-2 | 审阅队列（分类版） | 每条建议展示：书签、建议路径、置信度、理由；单条接受/拒绝/改分类；批量接受高置信度 | `SuggestionReview.tsx` | 建议实体从"标签"换为"分类路径"；复用交互框架 |
| C2-3 | 拖拽重分类 | 书签拖到任意分类节点即改主分类；记录反馈 | 暂无拖拽 | 新增；写入 `ai_feedback`（action=modified） |
| C2-4 | 分类节点管理 | 新建/重命名/删除/合并分类；删除时子项上移；合并走审计日志 | 标签 CRUD + `merge.ts` + `tag_merge_log` 全部可复用 | 无（标签树即分类树，D4） |

### C3 托管文件夹回写（分类 → 书签栏）

|---|---|---|---|---|
| C3-1 | 构建分类结构 | 在书签栏 `TagNest` 托管文件夹内按分类树创建文件夹并放置书签 | `resolveSyncFolder()` 只会建平铺文件夹 | 重写为树构建器：按 `categoryPath` 建多级文件夹 |
| C3-2 | 回写前预览 | 展示将创建哪些文件夹、移动哪些书签（数量 + 抽样），确认后执行 | 无 | 新增 diff 预览（扩展端计算） |
| C3-3 | 回写前快照 | 执行前对托管文件夹做完整本地快照 | `SYNC_BACKUP_KEY` 备份机制已有（仅备份被改动节点） | 扩展为整树快照 |
| C3-4 | 一键撤销 | 回写后可恢复到执行前状态 | `rollbackSync()` 已有 | 复用并覆盖整树场景 |

## 4. 数据模型变更

新增一次迁移（`0024_primary_category.sql`）：

```sql
-- 书签唯一主分类（单一归属，D2 决策）
CREATE TABLE IF NOT EXISTS bookmark_primary_category (
  bookmark_id  TEXT PRIMARY KEY REFERENCES bookmarks (id) ON DELETE CASCADE,
  tag_id       TEXT NOT NULL REFERENCES tags (id) ON DELETE CASCADE,  -- 分类树节点（叶子或中间层）
  confidence   REAL,                    -- AI 置信度；手动指定为 NULL
  source       TEXT NOT NULL DEFAULT 'ai',   -- ai | manual | browser_folder | import
  job_id       TEXT,                    -- 产生该归属的分类任务
  status       TEXT NOT NULL DEFAULT 'accepted',  -- pending | accepted | rejected
  decided_at   TEXT,
  updated_at   TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_bpc_tag ON bookmark_primary_category (tag_id);
CREATE INDEX IF NOT EXISTS idx_bpc_status ON bookmark_primary_category (status);
```

设计说明：

- **不新建分类树表**：分类树 = 标签树（D4），`tags.parent_id` 已就位，合并/别名/私密级联等能力全部复用。
- **不动 `bookmark_tags`**：辅助标签照旧；主分类路径由 `bookmark_primary_category.tag_id` 沿 `parent_id` 上溯推导。
- **`sync-pull` 的 `categoryPath` 是派生字段**：查询时 JOIN 推导，不加存储列，避免双写不一致。
- 既有 `tag_suggestions` 继续承载"标签建议"；分类建议复用同表并加 `kind` 列（`'tag' | 'category'`，默认 `'tag'` 兼容存量），或独立轻量表——实现时二选一，倾向前者（审阅 UI 统一）。

## 5. 接口变更

### 5.1 新增

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/category/tree` | 分类树 + 每节点书签数；`?format=writeback` 时返回全量 `{bookmarkId, url, title, categoryPath}` 映射（供扩展建树，分页） |
| POST | `/api/category/assign` | 手动/拖拽重分类 `{bookmark_ids[], tag_id}` → 更新主分类 + 写反馈 |
| POST | `/api/ai/categorize` | 创建精确分类任务（或复用 `/api/ai/jobs` 加 `kind:'categorize'`，实现时定） |

### 5.2 修改

| 端点 | 变更 |
|---|---|
| `GET /api/bookmarks/sync-pull` | 响应项增加 `categoryPath: string[] \| null`（派生，见 4 节） |
| `POST /api/bookmarks/sync-push` | `upsert` 变更增加可选 `categoryPath?: string[]`；携带时按名称解析/创建分类节点并更新主分类（`source='browser_folder'`），解析失败记入 `errors` 不中断批次 |
| `GET /api/ai/suggestions` | 支持 `kind=category` 过滤 |
| `POST /api/ai/suggestions/apply` | 分类建议落库时写 `bookmark_primary_category` 而非 `bookmark_tags` |

### 5.3 错误与幂等约定

- `categoryPath` 解析遵循既有标签唯一约束（`idx_tags_user_name`，大小写不敏感），同名复用不新建。
- `sync-push` 保持"单条失败不中断批次 + 逐条报错"语义（现有 `MAX_CHANGES=500` 上限不变）。
- 分类任务复用既有幂等机制（`op` 级去重、断点续跑）。

## 7. 关键交互流程

### 7.1 首次整理（100+ 乱书签 → 分类书签栏）

```
① 扩展"授权并对账" → 上传浏览器书签（含原文件夹路径作参考信号）
② 网页 /organize → 选择"精确分类"模式 → 成本预估 → 确认运行
③ 分批分类（内容理解 + 既有树约束）→ 高置信度自动落库，其余进审阅队列
④ 用户审阅/拖拽微调 → 全库获得唯一主分类（未分类 ≤10%）
⑤ 扩展"构建分类书签栏" → 预览（将建 N 个文件夹、放置 M 条书签）
⑥ 确认 → 整树快照 → 分批构建托管文件夹 → 完成
⑦ 书签栏出现 TagNest/开发技术/前端开发/… 的整齐结构
```

### 7.2 多浏览器切换

```
新电脑/新浏览器装扩展 → 填服务器地址 + API Key（命名"公司 Edge"）
→ 点"从云端构建分类书签栏" → 拉取 /category/tree?format=writeback
→ 本地建树 → 完成。之后每次同步增量对齐。
```

### 7.3 日常增量（双向）

```
浏览器在托管文件夹内移动书签 → 扩展检测文件夹变更
→ 上行 {url, categoryPath} → 云端更新主分类 + 写反馈（越用越准）
→ 另一浏览器下次同步时 sync-pull 携带新 categoryPath → 本地移动到对应文件夹
```

## 8. 权限控制与异常处理

### 8.1 权限

| 层 | 规则 |
|---|---|
| 数据隔离 | 主分类表与所有新端点强制 `user_id` 过滤（沿用既有模式） |
| 私密边界 | 私密/类别私密书签**不进入**分类任务、不出现在 `categoryPath` 推导与托管文件夹（沿用 `PRIVATE_BOOKMARK_CLAUSE`） |
| API Key | 扩展 Key 需 `write` 作用域；`/api/keys`、`/api/auth/*` 依旧禁止 Key 访问 |
| 回写范围 | 扩展对浏览器书签的写入严格限定托管文件夹内（C3-7 回归测试断言） |

### 8.2 异常处理

| 场景 | 策略 |
|---|---|
| 分类任务模型不可用 | 域名兜底给一级粗分类 + `needsReview`，不阻塞（沿用现有降级） |
| 回写中断（断网/关浏览器） | 已建部分保留；下次"继续构建"从快照对比续建（幂等） |
| 托管文件夹被用户整体删除 | 下次同步检测到缺失 → 提示"重建分类书签栏"，不自动重建 |
| 同名文件夹冲突（用户手动建了同名） | 复用既有文件夹（按标题匹配），不新建重复 |
| 分类路径解析失败（上行） | 该条记入 `errors`，书签本体照常 upsert，分类留待下次对账 |
| 大量书签同时移动 | 分批 ≤50/批 + 进度；chrome.bookmarks 报错逐批重试一次 |
| 云端分类与本地文件夹不一致且无法判定先后 | 标冲突 badge，同步页手动裁决"保留本地文件夹 / 采用云端分类"（沿用现有冲突 UI） |

## 11. 风险点
