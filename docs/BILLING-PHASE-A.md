# AI 托管计费 — Phase A 脚手架（2026-08-27）

## Why（为什么做）

TagNest 目前是「自托管全功能 + 自带 API Key」模式：AI 整理能力完整，但每个用户必须自己搞一把 OpenAI/Anthropic/Gemini 的 Key。这道门槛把两类价值挡在门外：

1. **零配置用户**——想「注册即用 AI」，不愿意先去模型商注册、绑卡、管 Key；
2. **付费意愿**——产品没有任何可售卖的托管层，收入无从谈起。

Phase A 的目标不是收钱，而是**把计量与门控先跑通**：先能精确回答「谁、用了多少、还剩多少」，支付网关（Stripe/Polar，待选型）后续可以无侵入地挂上来。

## Non-goals（本期不做）

- ❌ 支付网关接入（Stripe/Polar 等，待选型 + 商户凭据）
- ❌ 自助升级/降级/取消订阅的结账流程
- ❌ 按 token 精确计费（本期 1 额度 = 1 条书签，可预期性优先）
- ❌ 团队席位管理（`team` 计划仅占位）
- ❌ 用量报表导出、发票

## 用户故事

- 作为**零配置用户**，我希望开通试用后不填任何 Key 就能跑 AI 整理，以便先体验价值再决定是否付费。
- 作为**付费用户**，我希望在设置页看到剩余额度与消耗，以便对「钱花在哪」有确定感。
- 作为**付费用户**，我希望随时关闭托管模型开关，以便确保网站不会在我不知情时消耗我的额度。
- 作为**运营者**，我希望用一条管理员命令给指定邮箱发放试用，以便做种子用户运营。
- 作为**自托管用户**，我希望计费表的存在不影响我——我用自己的 Key，行为与从前完全一致。

## 架构

### 数据层（`migrations/0025_billing.sql`）

| 表                             | 职责                                                                               |
| ----------------------------- | -------------------------------------------------------------------------------- |
| `ai_settings.managed_enabled` | 用户对托管推理的**同意开关**，默认 1（托管账户零配置）                                                   |
| `subscriptions`               | 每用户一行：`plan`（free/pro/team/admin）+ `status`（none/trialing/active/canceled）+ 到期时间 |
| `ai_credit_balances`          | 实时额度表：`balance`（可花）+ `used`（累计），主键点查                                             |
| `ai_credit_ledger`            | 只追加流水：每次扣减一行，任何争议可重建                                                             |

缺行即降级：没有订阅行 = free/none，没有余额行 = 0/0——永远不阻塞推理路径。

### 决策层（`functions/_lib/ai/billing.ts`）

单一决策点 `getEffectiveAiConfig(env, userId)`，四个 AI 调用点统一走它：

```
自己的 Key 就绪？ ──是──> 用自己的（不计量）
      │否
实例配置了托管模型（MANAGED_AI_KEY）？ ──否──> null（兜底域名标签）
      │是
订阅有效（非 free、非 none/canceled）
 且 managedEnabled 同意
 且 balance > 0 ？ ──否──> null
      │是
用托管配置（复用用户的自动化偏好，只换「谁的 Key 付钱」）
```

关键性质：

- **自有 Key 永远优先**——付费用户不会被白白扣额度；
- **计量是 best-effort**——`consumeAiCredit` 只在 `engine === 'model'`（真实模型调用）后触发，且失败只吞日志，绝不把用户的保存/整理操作搞挂；
- **免费自托管零感知**——BYO-Key 部署在第一个分支就短路，从不触碰计费表。

### 端点

| 端点                                | 鉴权                 | 说明                                                          |
| --------------------------------- | ------------------ | ----------------------------------------------------------- |
| `GET /api/billing/status`         | 登录用户               | 返回 `BillingInfo`：套餐、状态、额度、同意开关、实例是否有托管模型                    |
| `POST /api/admin/grant-pro-trial` | 登录 + `ADMIN_TOKEN` | 按邮箱发放/续期试用（幂等：追加额度、延长窗口）。未配置 ADMIN_TOKEN 返回 503，令牌不匹配返回 403 |

管理员门控用 `ADMIN_TOKEN` secret + 常量时间比较，而非 `users.role` 列——自托管产品不引入角色体系，运营者用 `wrangler pages secret put ADMIN_TOKEN` 配置。

### 前端（设置页「用量与订阅」区块）

1. **套餐与额度**——套餐/状态徽章 + 余额卡片；仅当 `managedAvailable` 时渲染，自托管实例显示一行说明而非假仪表；
2. **托管 AI 开关**——`managedEnabled` 同意开关，即时生效、刷新保持；
3. **管理员发放试用**——邮箱 + 令牌（每次手输、不落盘）+ 套餐/额度/天数。

## 环境变量

| 变量                    | 必填      | 说明                      |
| --------------------- | ------- | ----------------------- |
| `MANAGED_AI_KEY`      | 托管层必填   | 托管模型 Key；未设 = 托管层整体关闭   |
| `MANAGED_AI_MODEL`    | 否       | 默认 `gpt-4o-mini`        |
| `MANAGED_AI_BASE_URL` | 否       | OpenAI 兼容网关地址（可指向自部署模型） |
| `ADMIN_TOKEN`         | 管理员接口必填 | 未设 = 管理员端点一律 503        |

均通过 `wrangler pages secret put` 配置，不进 `wrangler.toml`。

## 计量口径

**1 额度 = 托管模型分析 1 条书签。** 按书签而非按 token：用户在跑整理前就能从成本预估（`estimateJob`）知道确切花费，可预期性优先于绝对公平。扣减点：

| 调用点         | reason                                 | 单位         |
| ----------- | -------------------------------------- | ---------- |
| 保存书签自动整理    | `ai.enrich`                            | 1          |
| 即时重新分析      | `ai.suggest`                           | 输入条数       |
| 批量作业（打标/分类） | `ai.job.tagging` / `ai.job.categorize` | 每 chunk 条数 |
| 别名生成        | `ai.aliases`                           | 词条数        |

兜底引擎（`fallback`/`none`）产出永远免费。
